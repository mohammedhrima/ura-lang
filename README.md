# Ura

A compiled, statically typed language with Python's indentation and C's speed. No braces, no semicolons. The compiler is written in C and uses LLVM only for the last step, turning IR into native code.

The compiler is being rewritten from scratch, one milestone at a time. This file is the list of everything it has to do. Each feature is tagged with the old compiler that had it: 001 (the biggest, 7467 lines), 002 (3690 lines), 003 (the latest, 3519 lines). The three are kept in src/old. A feature with no tag is new.

## Layout

+ README.md: this file.
+ LICENSE, .gitignore, .clang-format, .vscode (settings.json, c_cpp_properties.json).
+ src/main.c: the compiler core (tokenizer, parser, analyzer, IR emission). It never calls LLVM directly. Empty for now.
+ src/ir.c: the IR, its builder, and the bridge to LLVM. The only file that includes LLVM headers. Not written yet.
+ src/proto.h: prototypes of every function in main.c and ir.c, generated by build.
+ src/config.sh: the task shell (build, tests, record, copy).
+ src/old: the three previous compilers, for reference.
+ tests: milestone0.md (the specification of the LLVM wrapper, not a test file) and one test file per milestone, milestone1.md to milestone13.md.

Removed during the cleanup: src/random (the legacy tests, the standard library written in Ura, the example projects, the old docs), src/tests, TODO.md, and the build outputs. They are all in git history, at commit 6039042 ("remove the vscode extension (snapshot before cleanup)"). For example: git show 6039042:src/random/ura-lib/string.ura. The git tag "legacy" is meant to point at that commit.

## Build and test

### Requirements

+ Linux, clang, and LLVM 12 (llvm-config 12).
+ Universal Ctags (optional): build uses it to regenerate src/proto.h. Without it, the committed proto.h is used.

### Commands

Run these from src after loading the task shell with: source config.sh

+ build: compile the compiler into bin/ura.
+ ura file.ura -o exe: compile a program. The LLVM IR goes to build/out.ll in the current directory.
+ tests: rebuild, then run every milestone file.
+ tests milestone1: run one milestone. tests milestone1 4 runs only its entry 004.
+ record milestone5: rebuild, then record the IR (or the error output) of every entry of that file. Use it when a milestone starts, and after a change made on purpose.
+ copy file.ura milestone1 "title": add a program as a new test entry, with its recorded output.

### Test files

+ Milestone N contains every feature of the milestones before it. Its test file only adds the tests for its new features. Running tests runs all of them, so old milestones keep guarding against regressions.
+ Each entry has a number, a title, a Ura program, and either its recorded LLVM IR or its stderr and exit status.
+ Comments on top of a program say what it should do: expect (the exit code), stdout (one line per printed line), stderr (a runtime message), error and help (for compile error tests). The runner compares IR and stderr, not runtime output, so run each program by hand once and check these comments.
+ Milestones 1 to 4 are recorded: they hold the IR the previous compiler produced. Milestones 5 to 13 are not recorded yet. Their programs were rewritten from the legacy tests with the syntax changes that are known (4-space indentation, fn main() i32: with return 0, fn f(): for void, r &i32 = &x for refs, bool). Features that have no new syntax yet (output, enums, match, new and clean, ref?, ??, try, @if, operator, pub, for) keep the old compiler's syntax. Fix the syntax of a milestone when you start it, then run record on it.

## How it works

### Pipeline

+ tokenize: source text to tokens, with indentation levels.
+ parse: tokens to a tree. Structs are declared before their scope's body is parsed, so they can be used before their declaration.
+ analyze: names, scopes, types, and errors.
+ IR: the analyzed tree is emitted into Ura's own IR (src/ir.c).
+ LLVM: ir.c lowers that IR to LLVM, writes build/out.ll, and clang turns it into an executable.
+ Later stages to add (ideas of 001 and the old roadmap): a pass that removes code for other platforms before parsing, a type check pass separate from name resolution, an IR lowering pass.

### The IR layer (src/ir.c)

The full specification is tests/milestone0.md; it wins where it differs from this summary (it describes an immediate builder, not the deferred IR sketched here). The core builds plain C structs and asks ir.c to lower them. Compiler logic never touches LLVMValueRef, LLVMTypeRef or LLVMBasicBlockRef. This removes from the core about 60 LLVM functions, the 17 LLVM typedefs of 003 (Value, TypeRef, Bloc and so on) and the Asm struct inside Token.

+ Type: void, integer of N bits, pointer to a type, array of a type with a length, struct (a name and a list of field types), function (return type, parameter types, variadic flag).
    + Types are unique: asking twice for pointer to i32 returns the same Type, so comparing types is comparing pointers.
    + A struct type is created by name before its fields are known. This makes structs usable before their declaration, and recursive types, simple.
+ Value: a type plus a name. It is a constant integer, the zero of a type (null, False, a zeroed struct), a global, a function parameter, a function, or the result of an instruction.
+ Instruction: an opcode, operand Values, a result Value, and a predicate for comparisons. Opcodes: alloca, load, store; address of a struct field; address of an array element; add, sub, mul, signed div, signed rem, and, or, not; compare (eq, ne, lt, le, gt, ge, signed); casts (sign-extend, zero-extend, truncate); call; memcpy (for string literals); branch, conditional branch, return.
+ Block: a name, a list of instructions, and an ends flag set by any branch or return.
+ Function: a name, a type, parameter Values, blocks, and an entry block that receives every alloca. A proto is a function with no blocks.
+ Global: a name, a type, and an initializer (zero, an integer, or a string constant).
+ Module: struct types, globals and functions, in creation order.
+ Every IR object has one opaque backend pointer. Only the lowering in ir.c writes and reads it.
+ All IR objects use the arena (ura_alloc), and their lists use the expand and push_back macros.
+ Builder, called by the core: a current function and a current block; start a function, create a block, move to a block, emit each instruction (each emit appends to the current block and returns the result Value). Alloca always goes to the entry block. Queries replace the LLVM calls of 003: the type of a Value, the element type of a pointer, whether the current block already ends, the return type of the current function. Names chosen in analyze (load.x, dref.p) are kept as given.
+ Lowering to LLVM, inside ir.c only: create every struct type opaque and by name, then set every body; declare every function and global; for each function create all its blocks first, then lower each instruction; verify the module, print build/out.ll, and hand it to clang. Names go through unchanged, so the recorded IR in the tests is also the regression check for the wrapper.
+ ir.c grows with the milestones: milestone 1 needs integers, bool, char, functions, protos, calls, blocks, branches, alloca, load, store, binary operations, compares, globals and string constants. Arrays and refs add element addresses and pointer types, structs add field addresses and struct types, casts add the cast opcodes.

### Errors

+ Every error shows the file, line and column, the source line with the faulty part underlined, and a help line when there is a likely fix.
+ All errors of a stage are collected and printed together. Compilation stops after the first stage that has errors (tokens, tree, analysis).
+ Warnings exist too (001): unused or unreachable code, an operator drop declared alone. A directive silences the next declaration.

### Command line

+ ura file.ura -o name: output name (default: the source's name). [001, 002, 003]
+ -O0, -O1, -O2, -O3, -Os, -Oz: LLVM optimisation level. [001]
+ -san: sanitizers and debug info. [001]
+ -tree: print the typed tree and stop. [001]
+ -ll: keep or print the LLVM IR. [001]
+ -exec: run the program after building it. [001]
+ -debug: verbose compiler messages. [001]
+ -testing: no colours, for the test runner. [001]
+ A missing argument for -o, or no input file, is an error with a usage message. [001]

## Milestones

### Milestone 1: programs that compute (96 tests)

Rebuilt from 003, with the error messages of 001.

+ Tokenizer: indentation is 4 spaces and anything else is an error. Line comments and block comments. Identifiers, integers, char literals, string literals with escapes.
+ Types: i32, bool (True, False), char (the same as i8). A declaration without a value starts at zero: x i32.
+ Operators: + - * / % (signed), == != < > <= >=, and, or, not, parentheses, precedence, unary minus. Assignment and the compound assignments += -= *= /= %=.
+ Control flow: if, elif, else, while, break, continue. A body can sit on the same line: if x > 1: n += 1. A variable declared in a block does not outlive it, and sibling blocks can reuse a name.
+ Functions: fn add(a i32, b i32) i32: with parameters passed by value, return, a bare return in a function without a result, recursion, mutual recursion, calls before the declaration, a call used as an argument. [003]
+ C functions: proto printf(fmt i8[], ...) i32, variadic calls, and string literals. Calling exit and the other libc functions through proto.
+ Global scope: variables declared outside functions are globals, a function can change them. Code outside functions runs at the start of main, and a file with no main gets one, like a Python script.
+ Errors: unknown character, unclosed string, char or comment, empty char, a char with two letters, number too big for i32, bad indentation, missing ':' or ')' or '(', missing function name, return type or parameter type, missing comma between parameters, unknown type, variable declared twice, used before its declaration, used outside its block, assigned without a declaration (with a did you mean help), function defined twice, wrong number of arguments, wrong argument type, calling a variable, using a void result, wrong return type, a number or string as an if or while condition, break or continue outside a loop, elif or else without an if, else with a condition. [001, 003]

### Milestone 2: memory and data (46 tests)

+ Arrays: a i32[] = [1, 2, 3], a[i], a[i] = v, array literals with variables in them, arrays of bool and char, an array passed to a function. A string is a writable i8 array. [003]
+ Refs: p &i32 = &x reads and writes x through p. p = 12 writes through. p = &y rebinds. Two refs to one variable see each other's writes. Ref parameters change the caller, swap works, a ref parameter can be passed on. A ref to a bool, a ref in a loop, compound assignment through a ref. [003]
+ Casts: x as i8, c as i32, flag as i32, char arithmetic. [003]
+ not and ! on bools. isNullable(x) and null. [003]
+ Errors: ref to a ref, missing type after &, a ref initialised with a value, address of a literal, of an expression, of a call or of an address, ref to the wrong type, a ref parameter given a value, null assigned to a value or compared with one, array type left unclosed, a size written inside the type, indexing a non-array, a string or non-integer index, mixed element types, an array put into a scalar, unclosed literal, missing comma between elements, a string into i8, a bool into i32, a number too big for i8, a struct into another struct. [001, 003]

### Milestone 3: structs (64 tests)

+ struct Point: with attributes, zero-initialised. Reading and writing attributes. Nested structs, structs as attributes, arrays of structs, copying structs by assignment, a struct as a by-value parameter, a ref struct parameter that changes the caller, a function that returns a struct. [002, 003]
+ A struct used before its declaration, declared inside a function, an if block or a loop, nested in another struct. The same name in nested scopes: the innermost wins. An unused struct emits no type. [003]
+ Methods: fn get() i32: inside a struct, with self. A method that changes self, methods calling siblings declared below, two structs with the same method name, methods on an array element or a nested attribute, methods on a ref receiver, overloading, chained calls on returned refs. [003]
+ Programs: linked list walked through ref attributes, and the longer programs of tests/milestone3.md.
+ Errors: struct without a name or colon, an expression in a struct body, attribute without a type or declared twice, struct defined twice, struct with no attributes, a struct containing itself by value (or two containing each other), unknown attribute and unknown method (listing what exists), a method called with wrong arguments, dot on a non-struct, a bare attribute or method call inside a method (it needs self), a method called on the type, self outside a method. [001, 003]

### Milestone 4: templates (8 tests)

+ Generic structs: a type parameter, methods that use it, two type parameters, two instances of one template, a template used inside itself, nested templates, a proto inside a template keeping its symbol, a function called with type arguments, sizeof of the type parameter. Each set of types gets its own struct, named like Box<i32>. [002, 003]
+ Decide the syntax when this milestone starts: the 003 form (a template<T>: block holding the struct, used as Box<i32>) or the shorter struct Box<T>:.
+ Errors: too many type arguments, a template used without type arguments, a parameter that is not a name, something else than a declaration in the body, missing colon. [001]

### Milestone 5: modules and imports (22 tests)

+ use "file": a relative import pulls in a sibling file, resolved against the importing file, subfolders included. A file imported twice (a diamond) is loaded once, silently. An import cycle warns and still compiles. A missing file is an error. [001]
+ use "@/name" loads the standard library, found next to the compiler binary or through the URA_LIB environment variable. [001]
+ link "name": link an external library, and URA_LINK_name for its path. Errors for an unclosed use or link path. [001, 002]
+ mod name: blocks, called with name::f(). Nested modules a::b::f(). Enums, structs and pub static methods inside a module, used as mod::Type. A module can be referenced before its declaration, and its functions call siblings without the prefix. Errors: empty module, anything but declarations in the body, unknown module, unknown member, a module member reached with a dot, wrong argument count. [001]
+ The os global: os.argc, os.argv, os.get(name), defined in a file that is loaded into every program. [001]
+ Not in 001: import only chosen functions (use "file" only f).

### Milestone 6: output and strings (22 tests)

+ output(a, b, c): prints any number of values, each formatted by its type, with no format string and no import. It expands structs (nested ones too), arrays (also 2D), follows a bound ref and prints null for an unbound one, and prints [Circular] instead of looping forever. [001]
+ errput(...): the same, on stderr. [001]
+ operator output() on a struct: custom printing, returning a string. [001]
+ The libc functions the compiler itself calls (printf, dprintf, calloc, free, write, exit, strlen, getenv) are declared in a library file, not hardcoded in the compiler. [001]
+ The String struct, in the standard library: create, from, from_int; len, empty, at, value, c_str; push, pop, join, assign, clear, grow; find, contains, starts_with, ends_with; upper, lower, trim, substr, replace, repeat, reverse; to_int, compare; the operators + += == != < > =, against a String or a char array. It frees its memory when it leaves scope (needs milestone 8). [001]

### Milestone 7: enums and match (22 tests)

+ enum Name: with variants. Values start at 0 and count up, an explicit value resets the counter, variants can sit on one line. An enum-typed variable compared to a variant, an enum as a struct attribute, a variant used as an array index or in arithmetic, a variant used before the enum is declared. [001]
+ match x: with case a, b: and default:. No fall-through. break leaves the match only, continue applies to the enclosing loop. [001]
+ Errors: an enum with no variant, a variant declared twice, an explicit value that is not an integer, a case with no value, a case type that differs from the subject, case or default outside a match, break outside a loop or match. [001]

### Milestone 8: heap, drop and array extras (41 tests)

+ new T allocates one zeroed struct and binds it to a ref?. clean frees it and nulls the reference; cleaning an unbound reference or cleaning twice is safe. A function can return new T through a ref? result. [001]
+ operator drop: a destructor with no parameters and no result. It runs at the end of the scope, on return (the returned local survives), on break and continue, on fall-through of an if block, in reverse order, for the structs a struct owns at any depth (not for what it borrows), and for globals. Calling .drop() by hand is an error, and clean on a struct value is an error. [001]
+ Arrays beyond the basics: sized arrays i32[N] with zero values, runtime-sized stack arrays, 2D and 3D arrays and matrices, arrays of structs (stack and heap), new i32[n] on the heap with clean, recursive clean of multi-dimensional arrays, clean nulling the array. [001]
+ Slices a[1..4] are views on the same storage (end excluded). .len on stack arrays, heap arrays, slices and multi-dimensional arrays. The ? guard a[i]? traps at runtime when the index or the slice range is out of bounds, or after clean. [001]
+ Errors: clean on a non-array or a struct, new without an array type, array size not an integer, range bounds not integers, .len on a non-array, empty array literal, destructor with parameters or a result. [001]

### Milestone 9: operator overloading and static methods (31 tests)

+ operator + - * / % == != < > <= >= and the compound forms += -= *= /= %=, plus & | ^ << >>, declared inside a struct. Two overloads of one operator with different right-hand types. == returning bool. operator = for deep copy on reassignment (not on declaration), and from an i32. An operator and a method on the same struct. [001]
+ pub fn: a static method, no self, called Type::method(). Two structs can declare the same pub fn. Static methods compose, also inside modules. [001]
+ Errors: operator outside a struct, operator without a symbol, no overload for an operator, assigning a different struct, a binary operator with mismatched scalar types, a compound operator with no overload, an instance method called with ::, a pub fn called with a dot, pub outside a struct or not followed by fn, :: on a type that does not exist. [001]

### Milestone 10: loops (13 tests)

+ loop: an infinite loop, left with break, with continue. [001]
+ for i in a..b: the range goes up when a is smaller and down when it is larger, the end is excluded. by sets the step (a positive integer, and it needs a range on its left). for x in arr walks the elements, for ref x in arr changes them in place, for without a variable, break and continue inside a for, a for over a struct-array or a 2D array attribute. [001]
+ Errors: for over something that is not iterable, for ref over a range, by without a range, a step that is not positive, a missing colon. [001]

### Milestone 11: more types and operators (31 tests)

+ Integer types i16, i64 and the unsigned u8, u16, u32, u64. Floats f32 and f64: literals, arithmetic, comparison, compound assignment, zero value, a literal taking the type of its target. Integer literals at the edge of each range, a negative literal at the low edge, a literal too wide for i32 keeping its width, a literal that does not fit its target as an error. [001]
+ Casts between f64, f32 and the integer types, char arithmetic cast back to char. A struct cannot be cast to or from a scalar. [001]
+ Bitwise & | ^ ~ << >>, the compound forms, unary minus. Bitwise operators on floats are an error. A comparison gives a bool, not an i32. [001]
+ Runtime traps: division by zero prints file:line and exits with 1, f32 division by zero traps too (no inf). [001]
+ sizeof(x) (with or without parentheses) and typeof(x), on scalars, chars, bool, literals, arrays and structs (struct sizes honour ABI padding, typeof gives the struct's name). The pointer type. [001, 003]

### Milestone 12: nullable values and errors (33 tests)

+ Optional types and null: a nullable return, a comparison with null, ?? gives a default and chains right to left until a value that is never null. A value that is never null widens into an optional, an optional cannot be put into a non-optional, null needs a target type. [001]
+ ref?: a nullable reference, bound at declaration, written through, guarded reads (m?) that trap when unbound. Ref results: a function returns a reference or null, a ref-returning call can bind a ref or be passed to a ref parameter, reads chained on a call. Ref attributes in structs, also pointing to their own struct, rebound in place (lst.head = ref lst.head.next). Linked list programs. [001]
+ try, catch and throw with the Error struct from the standard library. A throw is caught in the same function or by a caller, rethrown, nested. return inside a try returns from the function, break inside a try leaves the enclosing loop. An uncaught throw prints its message and exits. Code after a throw is dropped. [001]
+ Errors: comparing a never-null value with null, ?? on a value that is never null, a ?? chain that does not end in a non-null value, throwing something that is not an Error, catch without try, a ref attribute written with a value instead of a rebinding. [001]

### Milestone 13: function values and directives (23 tests)

+ Functions as values: store a function in a variable and call it, pass it as an argument (higher-order), a function typed parameter. A function that is nested inside another one but captures nothing; capturing an outer local is an error. Calling a null function value traps with file:line. Infinite recursion overflows the stack. [001]
+ ret as the short spelling of return, mixable with it. ret ref returns a reference, and fn f() ref T declares a function returning one. [001]
+ proto then definition, or definition then proto. A conflict between two protos, or with a library proto, is an error. A variadic call keeps C's default argument promotion. [001]
+ @if, @elif, @else: code for other platforms is dropped before parsing. unix matches macOS and linux; also linux, macos, windows. It works at the top level, around a proto, and to choose a value inside a function. @no-warn silences the warning of the next declaration only. [001]

## Beyond the milestones

Ideas from the old roadmaps and TODO lists that were never built. None of them has a test file yet.

### Language

+ Tuples and multiple return values with destructuring: a i32, b i32 = f(). (001 had a start.)
+ Containers List[T] (001 had a start), Map[K, V], Set[T].
+ const and immutable variables, type inference (:= or auto), type aliases, string interpolation.
+ Function overloading, default parameter values, named returns, closures and lambdas.
+ The range operator on its own (0..10), switch is replaced by match.
+ Struct embedding or inheritance, clone (deep copy) next to assignment (shallow copy).
+ Reference attributes in structs without a forced binding, references that can never be null, arrays that always have a len attribute, heap memory freed automatically, importing only some functions of a file.
+ Smart pointers, an optional garbage collector, a strict mode that stops silly code such as a null struct.
+ Concurrency: threads, atomics, async and await, channels.
+ A printf-style width trick for strings of known length: printf("%*s", len, s).

### Standard library (written in Ura, over proto)

The legacy library is in git history (git show 6039042:src/random/ura-lib/NAME.ura). It is a set of proto declarations over the C library, and it has to be rebuilt once use works (milestone 5).

+ common: loaded in every program: printf, dprintf, calloc, free, write, exit, strlen, getenv, and the os global.
+ header: loads the common set at once: ctype, errno, fcntl, io, math, memory, net, signals, stat, stdlib, string, time, unistd.
+ Imported on their own: error (the Error struct), dirent, raylib.
+ Still missing: input from stdin, file reading and writing, directories, assert(cond, message), a JSON parser, an HTTP client, a package manager (config file, install, versions).

### Compiler

+ Error recovery: count errors instead of stopping at the first, resume at sync points (a newline at the same indentation, a dedent, a top-level keyword), poison nodes that later stages skip, and cap the report at 25 errors.
+ Exhaustive semantic checks, one test per rule: conditions must be bool, array index types, a type of infinite size, operator signatures, tuple arity, the result of a void function, break and continue outside a loop, self outside a method, a pub fn using self, a read before any assignment, unreachable code and unused variables as warnings.
+ Multi-pass architecture, a written language specification kept next to the tests, incremental compilation for multi-file programs.
+ Tokenizer: check that (), [] and {} close. Show the failing token's location in internal messages.
+ Build: replace the bash and Python glue by a small tool of its own. Handle different versions of external libraries. Support macOS and Windows next to Linux. Instruction-level parallelism (SIMD) in generated code.
