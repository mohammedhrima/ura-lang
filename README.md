# Ura

A compiled, statically typed language with Python's indentation and C's speed. No braces, no semicolons. The compiler is written in C and uses LLVM only for the last step, turning IR into native code.

The compiler is being rewritten from scratch in milestones. The three previous versions are kept in src/old (001.c, 002.c, 003.c), and everything removed during the cleanup is reachable through the git tag "legacy".

## Build and test

### Requirements

+ Linux, clang, and LLVM 12 (llvm-config 12).
+ Universal Ctags (optional): build uses it to regenerate src/proto.h. Without it, the committed proto.h is used.

### Commands

Run these from src after loading the task shell with: source config.sh

+ build: compile the compiler into bin/ura.
+ ura file.ura -o exe: compile a program. The LLVM IR goes to build/out.ll in the current directory.
+ tests: rebuild, then run every milestone test file.
+ tests milestone1: run one milestone. tests milestone1 4 runs only its entry 004.
+ record milestone1: rebuild, then record the IR (or the error output) of every entry, after a change made on purpose.
+ copy file.ura milestone1 "title": add a program as a new test entry, with its recorded output.

### Test files

+ tests/ holds one file per milestone: milestone1.md, milestone2.md, and so on.
+ Each entry has a number, a title, a Ura program, and either its recorded LLVM IR or its stderr and exit status.
+ Comments on top of a program describe what it should do: expect (the exit code), stdout (what it prints), error and help (for error tests).

## How it works

+ tokenize: source text to tokens, with indentation levels.
+ parse: tokens to a tree. Structs are declared before their scope's body is parsed, so they can be used before their declaration.
+ analyze: names, scopes, types, and errors.
+ IR: the analyzed tree is emitted into Ura's own IR (src/ir.c): types, values, instructions, blocks, functions.
+ LLVM: ir.c lowers that IR to LLVM, writes the .ll file, and clang turns it into an executable.

### Files

+ src/main.c: tokenizer, parser, analyzer, IR emission. It never calls LLVM directly.
+ src/ir.c: the IR, its builder, and the bridge to LLVM. The only file that includes LLVM headers.
+ src/proto.h: prototypes of every function, generated by build.
+ src/config.sh: the task shell (build, tests, record, copy).
+ src/old: the previous compilers, for reference.
+ tests: one test file per milestone.

### Errors

+ Every error shows the file, line and column, the source line with the faulty part underlined, and a help line when there is a likely fix.
+ All errors of a stage are collected and printed together. Compilation stops after the first stage that has errors (tokens, tree, analysis).

## Milestones

Each milestone contains every feature before it. Its test file only adds the tests for its new features.

### Milestone 1: programs that compute (in progress)

+ Variables: i32, bool, char. A declaration without a value starts at zero: x i32
+ Operators: + - * / %, == != < > <= >=, and or, and the compound assignments += -= *= /= %=
+ Control flow: if, elif, else, while, break, continue. A body can sit on the same line: if x > 1: n += 1
+ Functions: fn add(a i32, b i32) i32: with parameters, return, recursion, and calls before the declaration.
+ C functions: proto printf(fmt i8[], ...) i32, and string literals with escapes.
+ Global scope: variables declared outside functions are globals. Code outside functions runs at the start of main, and a file with no main gets one, like a Python script.
+ Errors: unknown characters, unclosed strings and comments, numbers too big, bad indentation, missing ':' or ')', undeclared or misspelled names (with a "did you mean" help), wrong argument counts, break outside a loop.

### Milestone 2: memory and data

+ Arrays: a i32[] = [1, 2, 3], a[i], a[i] = v. A string is a writable i8 array.
+ Refs: p &i32 = &x reads and writes x through p. Ref parameters change the caller. p = &y rebinds.
+ Casts: x as i8, c as i32, flag as i32.
+ not and ! on bools, isNullable(x) for a zero value or a null ref, and null.
+ Errors for these features.

### Milestone 3: structs

+ struct Point: with attributes, zero-initialised. Nested structs, arrays of structs, struct copies.
+ Methods: fn get() i32: inside a struct, with self. Methods on refs, overloading, chained calls on returned refs.
+ A struct can be used before its declaration, and a struct can be local to a function or a block.
+ Errors: unknown attributes and methods (listing what exists), self outside a method.

### Milestone 4: templates

+ Generic structs: struct Box<T>: used as Box<i32>. Each set of types gets its own struct, and templates can nest.

## Roadmap

### From the old compilers, to bring back

+ Modules: use "file" imports, mod name: blocks, import loop detection.
+ Output: an output builtin with no format string, and errput for stderr.
+ Strings: a String struct (len, push, find, upper, trim, replace, ...), to_string, and printing structs.
+ More types: i8, i16, i64, unsigned integers, floats, sizeof, typeof.
+ Control flow: for over a range (for i in 0..10), match instead of switch, try and catch.
+ Memory: heap allocation and free, destructors called at scope exit, arrays with a len attribute.
+ Operator overloading, static methods (Type::method()), enums.
+ Conditional compilation per platform (@if linux:), optimisation levels, sanitizers.
+ C interop: linking external libraries.

### New ideas

+ Functions inside functions, closures, default parameter values.
+ const, type inference, type aliases, string interpolation.
+ Clone (deep copy) next to assignment (shallow copy).
+ Tuples and multiple return values; List, Map and Set.
+ Support for macOS and Windows.

### Compiler

+ Show more errors per run by recovering inside each stage.
+ A written language specification, kept next to the milestone tests.
+ Incremental compilation for multi-file programs.
